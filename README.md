# AuditdNexus

**AuditdNexus** — веб‑конструктор и мастер развёртывания для [Linux auditd](https://man7.org/linux/man-pages/man8/auditd.8.html). Он собирает правила аудита, конфигурацию rsyslog, команды установки и проверки в готовый пакет.

Открыть конструктор: **https://andrei-s96s.github.io/AuditdNexus/**

> AuditdNexus не подключается к серверу и не отправляет данные: все действия происходят прямо в вашем браузере.

Конструктор также создаёт `60-auditdnexus.conf`, `install-auditdnexus.sh` и `verify-auditdnexus.sh`. Настройки сохраняются в браузере; их можно экспортировать в JSON или передать ссылкой. Ссылка содержит конфигурацию, поэтому не добавляйте в неё секреты.

Для удалённой доставки укажите hostname/IP и порт 1–65535. Для TLS дополнительно укажите путь к доверенному CA на целевом сервере и установите сертификат по этому пути до запуска установщика. Имя коллектора должно соответствовать его сертификату. Генератор добавляет пакет `rsyslog-gnutls` и проверку имени сервера, как описано в [документации rsyslog](https://docs.rsyslog.com/doc/tutorials/tls_cert_client.html).

## Что можно настроить

- SSH, sudo и события авторизации;
- учётные записи: `passwd`, `shadow`, группы;
- systemd, hostname и настройки ядра;
- задания cron и at;
- сетевую конфигурацию и firewall;
- привилегированные команды;
- настройки и журналы auditd;
- Docker и другие container runtime;
- любые собственные абсолютные пути.

Для каждого своего пути можно выбрать события:

| Событие | Что фиксируется |
| --- | --- |
| `r` | чтение файла или каталога |
| `w` | запись и изменение содержимого |
| `a` | изменение атрибутов, владельца или прав доступа |
| `x` | запуск файла |

## Как использовать

1. Откройте сайт AuditdNexus.
2. Отметьте готовые пресеты, соответствующие вашей системе.
3. При необходимости добавьте свои пути в блоке **«Свои пути»**. Используйте абсолютные пути без пробелов, спецсимволов и компонентов `.` / `..`. Корень `/` не поддерживается. Ключ события: 1–31 символ, латинские буквы, цифры, `_`, `.` и `-`; первый символ — буква, цифра или `_`.
4. Проверьте сгенерированные правила справа.
5. Нажмите **«Скачать .rules»**.

Перед установкой удалите правила для программ или каталогов, которых нет на целевой машине. Набор путей отличается между дистрибутивами и конфигурациями.

## Установка правил

Сначала перенесите скачанный `auditdnexus.rules` на Linux‑сервер и положите его в каталог правил auditd:

```bash
sudo install -m 640 auditdnexus.rules /etc/audit/rules.d/auditdnexus.rules
```

Загрузите правила и убедитесь, что они активны:

```bash
sudo augenrules --load
sudo auditctl -l
```

Для загрузки правил через `augenrules --load` перезапуск демона не нужен. В RHEL управление auditd имеет особенности: `systemctl restart auditd` может быть запрещён; см. [документацию Red Hat](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/security_hardening/auditing-the-system_security-hardening).

Автоматический установщик запускайте из каталога со скачанными файлами. Он проверяет наличие файлов и CA для TLS до установки пакетов, а пути наблюдения — перед установкой правил. Отсутствующие пути нужно исправить или удалить в `.rules`.

## Проверка событий

Измените тестовый файл или выполните действие, которое должно быть зафиксировано, затем найдите события по ключу правила:

```bash
sudo ausearch -k ssh_config
```

Полезные команды:

```bash
# Статус auditd
sudo systemctl status auditd

# Все загруженные правила
sudo auditctl -l

# События за сегодня в удобном виде
sudo ausearch -ts today -i
```

## Важно

- Сначала применяйте новые правила в тестовой среде.
- Не включайте аудит чтения (`r`) для больших, часто используемых каталогов: это быстро увеличивает объём журналов и нагрузку на систему.
- Следите за свободным местом в `/var/log/audit/`.
- Правила должны соответствовать вашей политике безопасности и требованиям организации.
- AuditdNexus создаёт правила наблюдения за путями (`-w`). Для сложных сценариев — системных вызовов, архитектур `b32`/`b64`, фильтров UID/AUID — дополните файл вручную или обратитесь к документации auditd.

## Локальный запуск и тесты

Для просмотра достаточно открыть `index.html` или запустить статический HTTP-сервер в каталоге проекта. Зависимости нужны только для браузерных тестов:

```bash
npm ci
npx playwright install chromium
npm test
npm run test:browser
```

Для установленного системного Chromium можно задать `CHROMIUM_PATH=/usr/bin/chromium`. Тесты покрывают пресеты и профили, валидацию входных данных, восстановление конфигураций, 36 сочетаний параметров установки, скачивание и копирование файлов, ссылки и семь размеров экрана. Если установлен `rsyslogd`, дополнительно проверяется синтаксис TCP/UDP/TLS-конфигураций (TLS-проверка использует системный CA `/etc/ssl/certs/ca-certificates.crt`). Скрипты установки проверяются через `bash -n` и выполняются с имитацией `sudo`; тесты не устанавливают auditd и не меняют системные службы. Подключение к реальному TLS-коллектору и загрузку правил в ядро нужно проверять на отдельной тестовой машине.
